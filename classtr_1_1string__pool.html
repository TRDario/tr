Detailed Description

Container storing a series of immutable NUL-terminated strings in a single allocation.

tr::string_pool is designed for efficient storage and lifetime management of a series of immutable strings. Rather than allocating individual buffers for each string, all strings are packed sequentially inside a single, contiguous buffer. This eliminates allocation overhead and heap fragmentation for scenarios where several strings share a common lifetime and do not require mutability. The underlying buffer is dynamically resizable and may be reallocated when its capacity is exceeded.

The invalidation rules of tr::string_pool largely mirror those of std::vector: Any operation that triggers in a reallocation invalidates all iterators and views to strings in the pool. Appending without reallocation invalidates the end iterator. Erasing invalidates all iterators and views to strings starting from the first erased string to the end of the pool.

tr::string_pool on its own does not do any sort of caching or indexing of the strings it stores. This means that iterating through the string pool is linear with respect not to the number of strings, but rather the total number of bytes taken up by said strings. This also means that tr::string_pool does not provide a constant-time size() function returning the number of stored strings.

◆ reserve_bytes()

void tr::string_pool::reserve_bytes ( usize capacity)

Increases the capacity of the pool.

The capacity of a string pool is the amount of space that may be taken up by strings in the pool without requiring reallocation.

The capacity of a string pool may never shrink, so reserving a capacity smaller than capacity_bytes() does nothing.

Parameters
capacityDesired capacity (in bytes) of the pool.
Invalidation
If capacity exceeds capacity_bytes(), all iterators (including end()) and views to strings stored in the pool are invalidated. Otherwise, no iterators or references are invalidated.
Complexity
At most linear with respect to capacity.
Exception safety
If an exception is thrown, this function has no effect (strong exception guarantee).
